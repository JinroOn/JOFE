# 레거시 진단 안내 수정 및 검증 (#136)

## 변경 이유

`/diagnosis`가 실제로 제공하지 않는 약 66~86문항·2차 심화 진단·맞춤 추가 질문을 안내했다. 현재 흐름은 기본 정보 → 성향 진단 → 역량 진단 → 결과 확인이며, 역량 문항은 `/diagnoses/questions` 응답을 사용한다.

네 단계 안내와 각 화면의 총 단계 표기를 일치시켰다. 문항 수는 진단 화면에서 확인하도록 안내하며, 저장 완료된 응답부터 이어갈 수 있다고 설명한다. 기본 정보의 첫 단계 진행 막대도 1/4로 맞췄다. 질문·응답 저장·채점·이동 로직은 바꾸지 않았다.

## 팀원 작업 확인

2026-11-17 기준 `develop` `f9bee67`에서 작업했다. 팀원의 #134(마이페이지 동의 영역)와 #135(세션 만료 안내)는 이미 머지되어 diff와 화면 동작을 확인했다. 두 PR의 MyPage·Auth 파일과 백엔드는 수정하지 않았다. 작업 전 열린 별도 구현 이슈·PR이 없음을 확인하고 #136을 먼저 등록했다. 작업 종료 전에도 열린 PR은 운영 배포 #111뿐이었고 `develop` 기준점은 동일했다.

## 검증 결과 (2026-11-17)

- `npm test`: 기존 API·이력·점수 회귀 37개 모두 통과.
- Chromium 화면 검증 10항목 통과, 페이지 JavaScript 오류 0건.
  - 데스크톱 네 단계 순서, 문항 안내, 저장 안내, 잘못된 심화·고정 문항 수 표현 제거.
  - 390px·320px 모바일 가로 넘침 없음, 시작 버튼 클릭 가능.
  - 탐색형 플래그가 꺼진 경우 탐색형 진입 주소가 레거시 안내로 이동하고 탐색형 API를 호출하지 않음.
  - 시작 버튼 → 기본 정보, 기존 회차 이어하기, 첫 단계 1/4 표시.

  - 성향 12응답 → 서버 응답의 역량 3문항 표시, 2/4·3/4 단계 표시, 새로고침 후 저장 답변 복원.
  - 객관식·서술형 완료 → 점수 산출·결과 생성 요청 후 결과 화면으로 이동, 별도 심화 단계 없음.
  - #134: 데스크톱·모바일에서 체크박스 중앙의 실제 클릭 대상 확인, 마케팅 동의 클릭·저장, 탈퇴 창이 열리지 않음.
  - #135: 401 및 갱신 실패 후 새 만료 문구 표시, 다시 로그인/홈 이동, 로컬 로그인 상태 초기화.
  - 로그아웃 상태에서 진단 안내 접근 시 로그인 화면으로 이동.

화면 검증은 로컬 프론트 `127.0.0.1:5177`, 탐색형·mock 플래그 모두 false에서 별도 API 응답 자료로 실행했다. 3개 역량 문항은 동적 문항 수와 객관식·서술형 흐름을 확인하기 위한 검증 자료이며 실제 서버 문항 수를 의미하지 않는다. 실제 사용자 데이터 변경·모델 호출은 없었다. 실행 자료·보고서·스크린샷은 Git에서 제외한 `output/playwright/legacy-intro-136-*`에 보관한다.

이 검증은 운영 API·배포 환경이나 가입부터 플랜까지의 실제 서버 전체 회귀를 검증한 것이 아니다. 운영 배포 PR #111의 환경변수·API 대상·스테이징 회귀 확인은 계속 필요하다.
